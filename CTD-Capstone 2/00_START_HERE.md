# Start here — CTD capstone workspace

This is a ready-to-open **local project folder** for VS Code and Claude Code. Its contents reflect the working dates supplied on **October 21, 2026** and the documents already available, not a completed project or a faculty-approved final concept.

## Set up VS Code and GitHub

1. Extract the ZIP and put the `CTD-Capstone` folder somewhere permanent on your computer (e.g., Documents).
2. Open that folder in VS Code (`File` → `Open Folder`).
3. Install the official **Claude Code** extension and sign in. In a Claude Code session, ask it to read `CLAUDE.md`, `Project-Management/Current-Status.md`, and `Project-Management/Working-Timeline.md`.
4. Start with the text in `Claude-Setup/First-Prompt-VSCode.md` to get help with this week's research. Read suggested changes before giving file-editing permission.
5. In VS Code's **Source Control**, initialize a Git repository. Make an initial commit, and publish to GitHub as a **private** repository. Review what is staged first. GitHub authentication may be required.
6. In the new **Claude Code Project**, connect that GitHub repository in the Context section. Give it the short Goal described below. Put the contents of `Claude-Setup/Project-Instructions.md` into its **project instructions** field (the exact settings label may vary by version).
7. In your new Claude Project conversation, send the text in `Claude-Setup/First-Prompt-Project.md`.

## Local vs cloud

- Local Claude Code in VS Code works on your actual local folder.
- A cloud Claude Project can reference the repository when connected; **local edits are not reflected on GitHub until committed and pushed**. If the Claude Project can sync files, use its sync control after pushing.
- Cloud changes may come back via a branch/pull request; review and merge them before pulling into VS Code.
- Keep the lasting record in the repository, not only in chats. Never assume cloud sessions have direct access to unpublished local files.

## Privacy and guardrails

- Never commit passwords, API keys, private interview recordings, identifying participant details, or restricted class materials without considering permissions and access controls. A private repository is not the same as guaranteed confidentiality.
- Request consent before collecting or recording visitor data; consult faculty about biofeedback and any university review requirements.
- Ask for approval before deleting, overwriting, sharing publicly, committing final creative choices, or creating paid cloud resources.
